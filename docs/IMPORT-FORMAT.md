# 导入格式说明（IMPORT-FORMAT）

> 导入支持 **JSON / CSV / TSV / Markdown(.md) / XLSX / DOCX** 六种来源，全部在浏览器本地解析（零第三方库）。
> 解析规则变化时须同步更新本文档与 `js/importers/adapters.js`、`js/importers/line-parser.js`。

## 1. 标准题目模型

所有来源最终统一为该模型（字段可缺省）：

```json
{
  "type": "judge | single | multi | fill | essay",
  "question": "题干（必填）",
  "options": [{ "letter": "A", "text": "选项内容" }],
  "answer": "B",
  "blanks": [{ "answer": "def", "accept": ["Def", "DEF"], "hint": "提示" }],
  "reference_answer": "参考答案文本",
  "analysis": "解析",
  "category": "分类",
  "source": "来源/原题号",
  "difficulty": 0,
  "tags": ["标签1", "标签2"]
}
```
> `difficulty`：0=未设置，1–5 从易到难（中文 易/较易/中等/较难/很难 自动归一）；`tags`：多标签数组（字符串可按 `、,，;；|` 分隔自动拆分）。二者是**题元数据**，不参与 contentHash 去重，编辑它们不影响错题/收藏键。

各题型字段：

| type | 必填 | `options` | `answer` / 其它 |
| --- | --- | --- | --- |
| `judge` | `question` | 忽略（渲染固定两项） | `answer` 为 正确/错误（归一支持 对/错/√/×/T/F/是/否） |
| `single` | `question`,`options`,`answer` | 必需 | `answer` 单字母，如 `"B"` |
| `multi` | `question`,`options`,`answer` | 必需 | `answer` 字母串，如 `"ABD"`（乱序/大小写均可，自动排序去重） |
| `indefinite` | `question`,`options`,`answer` | 必需 | 不定项选择，结构同 multi；判分时全对满分、少选得半分、错选 0 分 |
| `fill` | `question`,`blanks` | 忽略 | `blanks[].answer`；`accept` 为可接受备选答案 |
| `essay` | `question` | 忽略 | `reference_answer` 参考答案（不自动判分） |

**题型可省略**：缺 `type` 时按「有选项→单选/多选；含 `____`→填空；答案为布尔词→判断；有参考答案→简答」自动推断。

### 1.1 各格式要求速查

| 格式 | 扩展名 | 必备结构 | 选项写法 | 注意事项 |
| --- | --- | --- | --- | --- |
| JSON | `.json` | 数组，或含 `questions` 数组，或 `{题型:{分类:[]}}` 嵌套 | `["A.文本"]` / `[{letter,text}]` | 编码 UTF-8；四种结构自动嗅探 |
| CSV | `.csv` | 首行表头，**必须含「题目/题干」列** | 「选项A…选项H」拆列，或选项列内含 `A.` 前缀 | 逗号/制表符/分号分隔自动识别；支持 BOM、引号转义、引号内换行 |
| TSV/TXT | `.tsv` `.txt` | 同 CSV | 同 CSV | 分隔符按首行自动判断 |
| Markdown | `.md` `.markdown` | `## 数字. 题干` 分题，`- **A.** 选项`，`**答案：X**` | `- **A.** 文本` 列表行 | 与本系统 md 导出格式对齐，支持导出→再导入往返；见 §6 |
| Excel | `.xlsx` | 每个工作表首行表头（同 CSV），按工作簿顺序合并 | 同 CSV | 读**全部工作表**（空表跳过），支持共享字符串/内联字符串/数字单元格 |
| Word | `.docx` | 题号分段，`A.`/`答案：`/`解析：` 标记 | `A. 文本` 行 | 必须严格按排版规范（见 §5），否则切题不准 |

通用要求：题干必填；单/多选题必须有选项与答案；警告（缺答案等）**不阻断**导入，可在预览页核对；去重键为「题型 + 规范化题干」。

## 2. JSON（`.json`）

自动嗅探以下结构：

### 2.1 标准数组
```json
[ { "type": "judge", "question": "…", "answer": "正确" }, … ]
```

### 2.2 本系统导出格式
```json
{ "app": "淬题", "version": "1.0.0", "bank": { "name": "…" }, "questions": [ … ] }
```

### 2.3 中文扁平（如 `题库-背题模式.json`）
```json
[ { "序号": 1, "题型": "单选", "题目": "…", "选项": ["A.…","B.…"], "答案": "B" } ]
```
> `选项` 支持 `["A.文本"]` 字符串数组，或 `[{ "letter":"A","text":"…" }]` 对象数组。

### 2.4 中文嵌套（如 `题库-分类.json`）
```json
{ "判断": { "类别A": [ { "题目": "…", "答案": "对" } ] }, "单选": { … } }
```
> 顶层键为题型名，二级键为分类；分类会自动写入 `category`。

## 3. CSV / TSV（`.csv` `.tsv` `.txt`）

第一行为表头。**必须包含「题目/题干」列**；其余按需。

```csv
题型,题目,选项A,选项B,选项C,选项D,答案,解析
单选,数据清洗的第一步通常是？,数据采集,数据清洗,模型训练,结果评估,B,先清洗再做建模。
多选,以下哪些属于数据质量维度？,完整性,准确性,一致性,及时性,ABCD,四项均为常见数据质量维度。
判断,SQL 中用于查询数据的关键字是 SELECT。,对,错,,,A,SELECT 用于查询数据。
填空,Python 中定义函数使用的关键字是 ____ 。,,,,,def,def 是定义函数的标准关键字。
简答,请简述数据库事务的 ACID 四个特性。,,,,,原子性、一致性、隔离性、持久性,ACID 是事务的基本保证。
```

**表头别名（中英兼容，忽略大小写与空格）**

| 目标字段 | 可识别的表头 |
| --- | --- |
| 题干 | 题目 / 题干 / 问题 / 试题 / question / stem / content |
| 题型 | 题型 / 类型 / 题类 / type |
| 答案 | 答案 / 正确答案 / 标准答案 / answer / key / correct |
| 解析 | 解析 / 答案解析 / 试题解析 / analysis / explanation |
| 分类 | 分类 / 类别 / 章节 / category / chapter |
| 来源 | 序号 / 编号 / 来源 / 题号 / source / id / no |
| 选项 | 选项A–H / optionA–H / A–H（单列多字母同理） |
| 填空 | 填空 / 空 / blanks |
| 难度 | 难度 / difficulty / level（1–5 或 易…难） |
| 标签 | 标签 / 知识点 / 关键词 / tags / keywords（多值用 、,；;｜ 分隔） |
| 参考答案 | 参考答案 / reference / reference_answer |

**要点**
- 编码 UTF-8（带不带 BOM 均可，自动剥离）；按首行自动识别逗号 / 制表符 / 分号分隔。
- 支持标准引号转义（`"` 写成 `""`）与引号内换行；字段内含逗号/换行/引号时请用双引号包裹。
- 选项可拆成 `选项A`…`选项H` 多列，也可合并到一列用换行/`A.` 前缀分隔。
- 判断题答案为字母（如 `A`）时，会结合选项文本（对/错）归一为「正确/错误」。
- 填空题多个空用 `；` `;` `|` `、` 分隔，与题干中 `____` 数量对齐。
- 本系统导出的 CSV 与本规范完全兼容（导出→再导入可往返，题量与题型分布不变）。

## 4. Excel（`.xlsx`）

- 读取**全部工作表**：每张表首行须为同一套表头（首行表头 + 数据行），按工作簿标签顺序合并，空表自动跳过；多表时预览警告区给出「N 个工作表合并 M 题」汇总。
- 原生解析：ZIP（`zip-reader`）→ `workbook.xml` + rels 解析表顺序与路径 → `sharedStrings.xml` / 各 `sheetN.xml` → `DOMParser`。
- 支持共享字符串（`t="s"`）、内联字符串（`t="inlineStr"`）与数值单元格。单表工作簿行为与旧版完全一致。

## 5. Word（`.docx`）

按段落排版切题。推荐格式：

```
1. 串联电路中，各处的电流相等。
A. 正确
B. 错误
答案：A
解析：串联电路电流处处相等。

2. SQL 中用于查询数据的关键字是？
A. SELECT
B. UPDATE
C. DELETE
D. INSERT
答案：A

3. Python 中定义函数使用的关键字是 ____ 。
答案：def

4. 请简述数据库事务的 ACID 四个特性。
答案：原子性、一致性、隔离性、持久性
```

**识别规则**
- 题号起始：`1.` / `1、` / `(1)` / `第1题` 等分隔题目。
- 选项行：`A.` / `A、` / `A)` 等。
- 标记行：`答案：` / `正确答案：` / `参考答案：`；`解析：` / `答案解析：`。
- 题型内联：题干中若含「（单选题）」等，会识别为对应题型。
- 无选项时：含 `____` 判定为填空，答案为布尔词判定为判断，含参考答案判定为简答。

> 解析结果不确定时，导入预览会给出**警告列表**（缺选项/缺答案等），请在预览阶段核对。

## 6. Markdown（`.md` `.markdown`）

纯文本格式，切题规则与 DOCX 共用同一套行式解析器（`line-parser.js`）。解析前先做轻量 Markdown 清洗：去掉标题井号、列表符（`-`/`+`/`*`）、加粗 `**`、行内反引号、引用前缀 `>`、整行分隔线（`---`）；**保留下划线 `_`**，故填空题干中的 `____` 不受影响。第一道题号之前的文档标题/导出信息自动忽略。

推荐直接使用本系统导出的 Markdown（导出 → 再导入可往返，题量、题型、答案一致），也兼容下列手写排版：

```markdown
# 我的题单

## 1. [判断] 地球是太阳系的行星。
**答案：正确**
> 解析：天文常识

## 2. [单选] 下列哪个是质数？
- **A.** 4
- **B.** 6
- **C.** 7
- **D.** 9
**答案：C**
> 分类：数学

## 3. [多选] 以下是偶数的是？
- **A.** 2
- **B.** 3
- **C.** 4
- **D.** 5
**答案：AC**

## 4. [填空] 定义函数用 ____ 关键字，返回值用 ____。
**答案：def；return**

## 5. [简答] 简述什么是闭包。
**答案：闭包是引用了自由变量的函数。**
```

**识别规则**
- 题号起始：`## 1.` / `1.` / `1、` / `(1)` / `第1题` 均可（井号与列表符会先被清洗）。
- 题型内联：紧跟题号的 `[单选]` / `[单选题]` / `（多选）` 等；缺省时按选项/空位/布尔答案推断。
- 选项行：`- **A.** 文本` 或 `A. 文本`。
- 标记行：`**答案：X**` / `答案：X`；`> 解析：…`；`> 分类：…`（分类会写入 `category`）。
- 填空各空答案用 `； ; | 、` 分隔，数量与题干 `____` 对齐。

> Markdown 主要面向**阅读与往返备份**；需要 Excel 打开请用 CSV，需要保留完整结构化字段（`source`、备选答案 `accept` 等）请用 JSON。

## 7. 校验与去重

导入预览会显示：**总题数 / 各题型数 / 警告 / 文件内重复数**。

- **去重键**：`type + normalize(question)` 的 FNV-1a 哈希（题干仅尾部空格差异视为同题）。
- **合并**：跳过与库内已存在的重复题；**覆盖**：清空目标库后写入。
- 警告（如缺答案）**不阻断**导入，但该题在答题时会判为未得分。

## 8. 网络地址导入（URL 快照）

http(s) 环境下可直接粘贴远端文件地址导入，与选择文件走**同一解析管线**：

- 仅允许 `http/https`，地址末段扩展名必须是受支持格式（json/csv/tsv/txt/md/markdown/xlsx/docx，查询串允许）。
- 15 秒超时；大小上限 **8MB**（先用 `Content-Length` 预检，读取后再按字节兜底；文本按 UTF-8 字节计）。
- 远端必须返回允许跨域的响应头（**CORS**）。无 CORS 的地址浏览器必然拦截，应用不做代理，请另存为文件后拖拽导入。
- 落地为**本地快照**：题库记录来源 `{kind:'url', uri, fetchedAt, checksum}`；首页显示来源徽章，「刷新网络来源」按 checksum 判断是否有变化，有变化才重新预览、合并去重。刷新是单向快照追加，不覆盖本地修改，不做双向同步。
- `file://` 双击打开时该入口禁用（浏览器安全限制）；需要时用 GitHub Pages 或 `node scripts/serve.mjs`。
- 不带凭据的公开地址；带 Token 的私有源属于未来 REST 后端范畴。
