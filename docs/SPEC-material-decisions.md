> 配套文档：[SPEC-material.md](SPEC-material.md)。本文对规格 §10 的 5 个决策点给出基于**当前代码事实**的选项对比与推荐，供评审拍板。
> 代码基线：2026-10-14，15 套件 2009 断言，commit `2b0e300`。
> 约定：每个决策给出「现状 → 选项 → 多维对比 → 风险 → 推荐」。推荐项标 ⭐。

## 决策 1：小问分值——固定 10 分/问，还是支持子问题权重？

### 现状（代码事实）

- `config.js`：`POINTS_PER_CORRECT=10`，全局默认分值常量；`quiz-engine.getScore()` 按题型分值计：`pointOf(type)`（本场 `pointsMap[type]` 优先，否则回落 10）+ 半对半分（不定项少选得半分）。
- 历史记录 `attempts.score` 是单整数；蓝图（`blueprint.js`）只有抽题数量概念，无分值。
- 练习题/考试开始弹窗（2026-10-19 起）可为**每个题型单独设「每题分值」**（仅本场生效、不写回题库）；材料题整题满分 = 各小问按「小问题型分值」累加（`QB.childPoints`）。未单设时仍为 10 分/题，跨题分数可比口径不变。
- 默认口径下所有现有题型满分一致（10），跨题分数天然可比，统计/历史 XLSX 导出按此口径；本场按题型覆盖分值后，仅影响本场得分展示，历史 `score` 仍记本场实际得分。

### 选项

| | A. 固定分值：每小问 10 分，整题 10×n | B. 子问题权重：`children[i].score`，整题 Σ |
| --- | --- | --- |
| 数据模型 | 无新字段 | 新增可选字段（缺省 10），需校验正整数/上限 |
| 引擎改动 | `getScore` 递归聚合即可 | 聚合时按权重计算，partial 要按 `score/2`（奇数分会出现 .5） |
| 编辑器 | 无需分值控件 | 每个小问一个分值输入框 + 校验 |
| 导入格式 | JSON/文本均无需分值语法 | JSON 加字段；MD/DOCX 需 `分值：5` 标记行；CSV 需「分值」列 |
| 文档/测试面 | 小 | 中（每格式往返都要验证分值保真） |
| 真实度 | 一般（公考材料题小问分值常为 2/3/5/10 不等） | 高，贴合试卷原貌 |
| 跨题可比性 | 保持（每问等权） | 被削弱，但本系统分数本就是自评练习分，非标准分 |
| 未来返工风险 | 后加权重要动模型+全部格式（破坏性迁移） | 一次定到位 |

### 风险与边界

- B 的 partial 计分：不定项小问少选时按 `score×0.5`，需统一舍入规则（建议保留 1 位小数，历史导出表已有「半对」列）。
- B 若允许 0 分小问会产生「答对不计分」的怪题，校验应拒绝 `score≤0`；上限建议 100。
- 只选 A 不代表永久排除权重：JSON 里**先允许读取**未知字段成本为零，但不写不暴露。

### ⭐ 推荐：**M1 固定 10×n，但标准模型预留 `children[i].score` 可选字段（缺省 10，引擎先读字段）；编辑器与文本格式配分推迟到 M4**

理由：①避免数据模型两次迁移（后加字段要补 JSON/MD/DOCX/CSV 全格式往返，破坏性最大）；②M1 引擎实现与 A 等成本，只是聚合时 `const pts = child.score||10`；③UI/格式复杂度按里程碑后置，与规格 M4「打磨」定位一致。评审若认为分值权重无真实需求，也可直接砍字段——M1 实现前删除零成本。

## 决策 2：错一小问的 SRS 档——整题 again，还是按错误比例宽容？

### 现状（代码事实）

- FSRS 优化器的训练样本是**二值伯努利**：`fsrs-train-core.js` loss 中 `y = rating===again ? 0 : 1`（还记得/没记住）。算法本身不理解「记住 80%」。
- 应用层已有一处「半对」先例：不定项**同一道题**少选 → hard（`app.js` 评分映射），语义是「单题记忆不完整」。
- again 后的成本并不高：进当日重学队列（1m/10m），当天对一次即毕业（SRS.md §4），不是「整张卡所有小问从零再学」。
- 错题本按整题收录（`WrongBook.add(bankId, question)`），错题练习从错题本抽整题。

### 选项

| | A. 任一子问错 → again（整题） ⭐ | B. 按错误比例：如仅 1/n 错记 hard，多于阈值才 again |
| --- | --- | --- |
| 信号语义 | 干净的二值信号，与优化器 y=0/1 完全一致 | 人为构造「部分记住」，阈值主观，优化器无法解释该样本 |
| 参数面 | 零参数 | 引入阈值（1/n？20%？）→ 新的用户可配置项/调参负担 |
| 实现 | 规格已定的三档映射，零额外代码 | grade 聚合要先算错误率再映射；文档/测试/UI 都要解释阈值 |
| 学习效果 | 错的知识点当天必再见（重学成本几分钟） | 错 1 小问只进 hard（次日级），薄弱点暴露延迟 |
| 挫败感 | 5 问错 1 问也判「忘」略严厉 | 温和 |
| 可解释性 | 「这道综合题没完全掌握」一句话清楚 | 「为什么错 1 个是 hard、错 2 个是 again」需要解释规则 |

### 关键洞察

材料题含多个知识点时，「错一个子问题该算什么」本质是**卡片粒度问题**，不是评分宽容度问题：

- 真正按知识点调度的解法是「材料 + 每个子问题各自成卡」，但那推翻 F4「整题原子」的产品决策，属于未来模型演进（材料库/子卡化）。
- 在「整题一卡」约束下，比例宽容只是用模糊信号换温和体验，且与优化器二值假设冲突。
- 现有的「错题练习」入口已经提供精准补救：错题本里可以只重做错题；可在结果页加「仅重练错的小问」按钮（体验补救，不动调度信号）。

### ⭐ 推荐：**A 整题 again**；体验侧用「结果页一键重练错误小问」缓解挫败感（M3），不引入比例阈值

若未来子卡化（材料与子问题拆成独立复习单元）落地，错误粒度问题自然消失；在那之前保持信号纯度。

## 决策 3：多小问含简答时，自评怎么做？

### 现状（代码事实）

- 简答题 `judgeAnswer` 返回 `isCorrect=null`，不自动判分。
- **练习模式**：每题提交后即时自评（`app.js` 练习即时判分，简答由用户点对/错）。
- **考试模式**：`gradeAll` 把 null 强制为 false 计入临时分，交卷前有确认对话框列出未自评简答，用户逐个自评后重算（`app.js` finishQuiz 流程）。
- 材料题在 M1 只是把这一机制「按小问」复用，不是新发明自评功能。

### 选项

| | A. 沿用双模式：练习逐小问即时自评；考试交卷后集中自评列表 ⭐ | B. 全部改为交卷后统一自评 | C. 练习也不即时，材料题特殊处理 |
| --- | --- | --- | --- |
| 与现有交互一致性 | 完全一致（普通简答今天就这样） | 练习体验回退（普通题即时、材料题滞后，规则割裂） | 产生「题型特殊流程」，认知成本高 |
| M1 实现量 | 交卷确认 dialog 从「单题简答列表」扩展为「(n) 小问 · 简答」多行列表 | 中 | 中 |
| 漏自评风险 | 有兜底（null→false 且明细确认），与现状相同 | 同 | 同 |
| 体验上限 | 一般（考试时 dialog 可能较长） | 同 | 同 |

### 风险与边界

- 一张材料题含 3+ 个简答小问时，确认 dialog 会很长——M1 可接受（滚动列表），**M3 优化为结果页内联自评控件**（每个简答小问卡片里直接放「我答对了/我答错了」），dialog 只做未自评兜底提醒。
- null 的统计语义不变：pending 数在交卷明细已展示；材料题的 pending 粒度为小问。

### ⭐ 推荐：**A**——M1 交卷确认流程扩展为「题号 + 小问号 + 参考答案 + 对/错」列表；M3 升级为结果页内联自评。无新交互范式，风险最低。

## 决策 4：共享材料——复制内嵌，还是建材料库实体？

### 现状（代码事实）

- 题目是自包含模型（question/options/… 全字段内嵌），`insertMany` 按 contentHash 去重落库，无跨题引用。
- 图片字节已在 IndexedDB 按内容寻址（`Assets.idFor` = FNV1a-长度），**即使两处文本引用同一图片，物理字节只存一份**。
- 备份（qfbk）/题库包（qbk）以题目为中心全量打包；材料库会引入新的引用实体。

### 选项

| | A. 复制内嵌：每道材料题自带 material 全文 ⭐ | B. 材料库：materialId 引用共享材料实体 |
| --- | --- | --- |
| 数据模型 | 零新表/新契约 | 新表（材料 CRUD）、引用完整性、级联策略、DATABASE §2 与 API-CONTRACT 全套 |
| 导入导出 | JSON 自包含，往返零特殊处理 | 导出要附带材料定义；导入处理 ID 冲突/多题共用/孤儿材料（复杂度接近 qbk assets 但文本可编辑） |
| 编辑一致性 | 改一处不影响他题（可接受，甚至是优点：两题材料本来就可微调） | 改材料影响所有引用题——需要「解除引用」「另存副本」操作 |
| 真实冗余成本 | 材料文本通常 200–800 字（~0.4–1.6KB）；图片不冗余（内容寻址） | 省文本，但 localStorage 配额下可忽略 |
| 用户真实场景 | 同卷内一个材料 + N 小问是「一道题」；跨题复用同一长材料少见 | 公考「资料分析」一个材料带多组题偶有跨题复用 |
| 竞品参照 | 个人版常见做法 | 考试宝企业版有独立「案例/材料」管理（团队协作场景） |
| 与后端化关系 | 现在能做，后端零改动 | 本质是内容管理功能，天然属于 `DATA_BACKEND=api` 议题 |

### 未来演进路径（选 A 不锁死）

即使 M1 复制内嵌，将来可平滑升级为材料库：

1. 先加只读视图：按 `hash(material)` 聚合展示「相同材料的题」（纯计算，不改模型）。
2. 真需要时引入 materials 表，迁移脚本把重复 material 提升为实体、回填 materialId；题目模型加可选 `materialId`（与内嵌 material 二选一），旧数据继续可读。
3. 反向（B→A）则困难得多：要拆引用、处理内联编辑历史。

### ⭐ 推荐：**A 复制内嵌**。理由：唯一真正昂贵的冗余（图片）已被内容寻址消除；材料库是团队/后端场景，在纯本地单机产品里提前付建模与引用完整性成本不划算，且 A→B 有平滑路径、B→A 没有。

## 决策 5：CSV/XLSX 是否兼容「单行写完整道材料题」？

### 现状（代码事实）

- 表格导入是**首行表头 + 每行一题**的扁平模型（`Adapters.tableToQuestions`），16 列固定；单元格内换行靠 RFC 4180 引号转义。
- 材料题是两层结构（材料 + N 子问题，每个子问题又有题型/选项/答案）。

### 选项

| | A. 仅多行块：首行材料 + N 行小问（新增「材料」「小问」两列） ⭐ | B. 额外兼容单行：首行单元格内用分隔语法编码全部子问 |
| --- | --- | --- |
| Excel 可编辑性 | 一行一小问，符合表格直觉；可用合并单元格美化 | 单元格里写迷你 DSL，不可阅读、无法用 Excel 功能筛选/排序 |
| 解析复杂度 | tableToQuestions 加块状态机（材料列非空开块、小问序号递增归组），与 LineParser 块概念同构 | 需要第二套嵌套转义：子问分隔符、字段分隔符、小问文本恰好含分隔符的歧义处理 |
| 往返可靠性 | 拆分/聚合规则确定，现有 538 题夹具可加材料题用例 | 极易产生往返损坏（引号/换行/分隔符三重转义） |
| 与现有表头映射 | 仅加 2 个可选列，旧表完全兼容 | 要在「题目」「选项A」等既有列里塞结构化内容，语义崩坏 |
| 实现/测试量 | 中（聚合器 + 正反往返断言） | 大（DSL 解析器 + 歧义用例 + 文档），收益仅「少占几行」 |
| 用户教育成本 | 一张示例表即可说明 | 需要讲解分隔符语法，违背零学习成本定位 |

### 多行块精确规则（决策 A 的落地约定）

```
题型     | 材料        | 小问 | 题目            | 选项A..D | 答案 | …
材料题   | 2026年……    |      | 根据资料回答：  |          |      | …  ← 块首：题型/材料/引导语，分类难度取此行
单选     |             | 1    | (1) 正确处理？  | A..D     | B    | …  ← 子问行
判断     |             | 2    | (2) 符合规定？  |          | 正确 | …
单选     |             | 1    | (下一题的小问)  |          |      | …  ← 「材料」列再次非空或小问序号归 1 → 新块
```

- 块结束条件：遇到下一个「材料非空行」或下一个非材料题行或文件结束。
- 校验：子问行必须有递增小问号（1..N），块内 2–10 个小问；违规整块警告、按普通题降级或拒绝（M2 定，建议拒绝并给行号）。
- XLSX 完全同构（同一二维表管线）；TXT/Markdown 不走此约定。

### ⭐ 推荐：**A 仅多行块，不做单行 DSL**。单行写法唯一优势是省行高，代价是表格导入最核心的「Excel 原生可编辑」属性丧失，且需要长期维护一套嵌套转义——与项目「原生简单格式」原则冲突。
