## `a25e4c1` · perf(sw): 命中先走精确匹配，去掉每请求的全表扫描

**背景**：首访（SW 已接管、缓存仅 CORE）实测 1612 ms。插桩定位到 `sw.js` 静态资源分支对**每个**请求都调用 `caches.match(req, { ignoreSearch: true })`：该选项让 CacheStorage 放弃 URL 索引、退化为线性扫描，123 条缓存时约 **17–20 ms/请求**，而精确匹配只要 0.1–0.3 ms。

**核心改动**
- `sw.js`：静态资源查询改为「先 `caches.match(req)` 精确匹配，未命中再 `caches.match(req, { ignoreSearch: true })`」。回退保留——staging 的 `?v=<version>` 请求必须能回退到无查询串的预缓存键，否则离线时按需包会全部落空。

**验证数据**
- 同夹具三相位（真实 Edge + CDP）：A/C 相位单请求 p50 **0.2–0.3 ms**；离线精确、`?v=` 回退、断网刷新语义不变。
- 离线可用性与版本化语义未改：回退路径仍在，只是不再对必然命中的请求先付一次全表扫描。

**遗留 TODO / 风险**
- 回退仍是无条件的：首访每个「精确未命中」的纯路径请求仍要付一次线性扫描。是否可收窄由 `bbaa41f` 处理。

## `26e3682` · perf(bench): 生产形态门禁按真实 verify 分布重定基线 13.595 / 阈值 14.41

**背景**：`SRSStore.gradeMany 批量 20 题（IDB + Quota ready）` 的初版基线 13.071/阈值 13.86 取自 20 个独立进程，但该门禁实际跑在 41 个套件之后，上下文不同：单跑 13.50，聚合态 3/3 落在 13.90–13.97。用「单跑绿」推聚合红属于口径错误。

**核心改动**
- `scripts/bench-baseline.json`：`node["26"].idbonGradeMany` 13.071 → **13.595**；容差 1.06 未动（= ceil2(13.98/13.595 × 1.03)）。
- 阈值随之为 **14.41**。
- `scripts/bench.mjs` 两处注释、`docs/BENCH.md` 3-B-3、`docs/BENCH-DATA.md` D-15 同步改写。

**验证数据**
- verify 上下文 20 次：中位 13.595 / max 13.98；独立进程 20 次：中位 13.500 / max 14.00；中位差 0.7%。
- A/B（基线提交 `3b41906` vs HEAD 各 8 次 standalone）：中位 13.66 vs 13.54，无系统性差异；机器较基线日慢约 4%。
- 新阈值 14.41 下干净态 **0/20 红**（旧阈值 13.86 下 3/20 + 2/20 误红）。
- 灵敏度：+30% 注入 3 次 **17.64 / 18.27 / 20.83（3/3 判红，最小余量 22.4%）**；+20% 三次 14.45 / 15.30 / 15.04（最小余量 0.3%，不承诺）。
- 噪声跨度 **11.93–14.00（约 18%）**；阈值高于噪声上沿 2.9%、低于 +30% 最小值 18.3%。

**遗留 TODO / 风险**
- 灵敏度按 **+30%** 写死；+10%/+5% 落在噪声内明确不承诺。
- 绝对比值门禁的分辨率受 18% 噪声跨度限制，且读数是 Node 内存 IDB 替身的**下界**，只能做同形态回归。
- 不自动复跑；阈值只由多日分布驱动调整，禁止按单日单次对齐当天机器。

## `bbaa41f` · perf(sw): 首访跳过必然落空的 ignoreSearch 回退，并修正 activate 清缓存顺序

**背景**：`a25e4c1` 后，首访纯路径请求仍在精确未命中时付一次线性扫描。统计真实场景「纯路径精确落空、靠 ignoreSearch 回退命中」为 **0 次**；但直接收窄回退不安全——只要缓存里存在带查询串的键（如 `?v=`、`?r=1`），纯路径请求的回退就可能命中。

**核心改动**
- `sw.js`：新增模块级「缓存里是否存在带查询串的键」探针（**宁真勿假**）：
  - `noteCacheWrite(url)` 在任何带 `?` 的 `put` 前**同步**置位并递增 `queryWriteSeq`；键被删除不清零。
  - `activate` 用一次全量 `caches.keys()` + `cache.keys()` 重算；扫描期间 `queryWriteSeq` 变化则按「有」处理；探测失败按「有」处理。
  - fetch 判定 `wantFallback = req.url.includes('?') || hasQueryKeys`；仅当请求不带查询串且探针为假时跳过回退。
- **顺序修正**：`activate` 由「删旧缓存 → claim → 重算探针」改为「重算探针 → 删旧缓存 → claim」。`caches.open()` 会创建不存在的缓存，原顺序下删除的存储层移除与新扫描交错，会把已删的旧版本缓存**重建成空缓存**（真实 Edge 复现：activate 后 `qforge-v87` 仍存在且 count=0）。
- `scripts/sw-runtime.test.mjs`：CacheStorage 替身支持 `ignoreSearch`/`keys()`/调用记录；新增探针 15 项断言（含「标志为假 ⟹ 回退与精确匹配返回值相同」的 no-op 断言）与「activate 后旧缓存对象不存在」断言。

**验证数据**
- 单测 **50/50**；变异 `--mutate` 49 通过 / 1 失败（exit 1，摘要漂移仍被抓住）。
- 真实 Edge e2e（全新 profile）**17/17**，连跑两次稳定：B 相位（裁剪回仅 CORE）p50 2.6 ms、87 条总耗时 231 ms；C 相位 p50 3.3 ms；断网精确 200、`?v=` 回退 200、`?r=1` 置位后纯路径回退 200、断网刷新可启动、首屏 87 个脚本全部 cache-storage、旧版本缓存被删且同源其他应用缓存保留。

**遗留 TODO / 风险**
- 探针为假的前提是「所有查询键写入都经过 `sw.js`」：若将来有代码绕过 SW 直接 `cache.put` 带查询串的键，标志会失真。当前站点无此类路径，已在 `sw.js` 注释与单测中钉住约束。
- 首访成本未归零的部分是网络本身（缓存仅 CORE 时脚本必须回源），不再有 SW 侧的线性扫描开销。
