# 导入格式 · 行式文本（Word / Markdown / 粘贴）

> **这份文件是什么**：`IMPORT-FORMAT.md` 的「§5 Word、§6 Markdown、§6.1 粘贴导入」三节。
> **为什么单独成文**：行式语法（题号 / `答案：` / `解析：`）是一套，改一处要三处同步；与表头规范分开放，改动才不会互相误伤。
> **节号沿用原文**（`§2`、`§3`…）——别处的「见 IMPORT-FORMAT.md §3」不必改号，
> 节号到文件的对照见 [IMPORT-FORMAT.md](IMPORT-FORMAT.md) 的索引表。

按段落排版切题。推荐格式：

```
1. 串联电路中，各处的电流相等。
A. 正确
B. 错误
答案：A
解析：串联电路电流处处相等。

2. SQL 中用于查询数据的关键字是？
A. SELECT
B. UPDATE
C. DELETE
D. INSERT
答案：A

3. Python 中定义函数使用的关键字是 ____ 。
答案：def

4. 请简述数据库事务的 ACID 四个特性。
答案：原子性、一致性、隔离性、持久性
```

**识别规则**
- 题号起始：`1.` / `1、` / `(1)` / `第1题` 等分隔题目。
- 选项行：`A.` / `A、` / `A)` 等。
- 标记行：`答案：` / `正确答案：` / `参考答案：`；解析类标记 `解析：` / `答案解析：` / `试题解析：` / `分析：` / `解题思路：` / `解题方法：` / `思路：` / `考点：` / `考查点：` / `考察点：` / `释义：` / `译文：` / `定义：` / `词义：`（可多次出现，按出现顺序合并到 `analysis`，多段加 `【标签】` 分段）。
- 题型内联：题干中若含「（单选题）」等，会识别为对应题型。
- 无选项时：含 `____` 判定为填空，答案为布尔词判定为判断，含参考答案判定为简答。

> 解析结果不确定时，导入预览会给出**警告列表**（缺选项/缺答案等），请在预览阶段核对。

### 5.1 DOCX 内嵌图片

- 识别对象：段落中的 DrawingML 图片（`<a:blip r:embed="rId…">`，Word/WPS 现代格式）与旧版 VML（`v:imagedata r:id`）；外链图（`TargetMode="External"`，即「链接到文件」模式）不下载、不支持。
- 关系解析：`word/_rels/document.xml.rels` 中 `…/relationships/image` 关系把 rId 映射到 `word/media/*` 字节；图片按 FNV-1a 内容寻址写入 IndexedDB（与 .qbk 同一套 `QB.Assets`，同图去重），题面段落插入 `![](asset:<id>)` 占位。
- 归属规则：图片与所在段落文本同行（内联于题干/选项/答案/解析段）；图片独占段落时按 LineParser 续行就近归入（题目编号后的独立图片段落续入题干；答案行之后的图片段落续入解析）。
- 容错：rId 在关系部件中缺失、或 `word/media` 内无对应文件时，该图跳过并在预览警告「N 张内嵌图片缺失」，题目文本照常切题，不阻断导入。
- 限制：页眉/页脚图片不取；文本框、SmartArt、嵌套表格内的图片归属可能不精确；导出端生成的 DOCX 目前不嵌图（仅文本往返），带图迁移请用 .qbk。

### 5.2 材料题块（M2-A）

DOCX 中材料题与 Markdown 使用**同一套行式材料块语法**（LineParser 共用）：顶层题号内联 `[材料题]` 开块，`材料：` 行给共享材料，`(1). [题型]` 起逐小问，下一个顶层题号自动收块。完整规则与容错见 [§6.1](#61-材料题块m2-a)。DOCX 段落即行：材料段落中的图片占位随材料正文进入 `material`，小问段落中的图片进入该小问题干（沿用 §5.1 就近规则）。样例：`示例-材料题.docx`。

## 6. Markdown（`.md` `.markdown`）

纯文本格式，切题规则与 DOCX 共用同一套行式解析器（`line-parser.js`）。解析前先做轻量 Markdown 清洗：去掉标题井号、列表符（`-`/`+`/`*`）、加粗 `**`、行内反引号、引用前缀 `>`、整行分隔线（`---`）；**保留下划线 `_`**，故填空题干中的 `____` 不受影响。第一道题号之前的文档标题/导出信息自动忽略。

推荐直接使用本系统导出的 Markdown（导出 → 再导入可往返，题量、题型、答案一致），也兼容下列手写排版：

```markdown
# 我的题单

## 1. [判断] 地球是太阳系的行星。
**答案：正确**
> 解析：天文常识

## 2. [单选] 下列哪个是质数？
- **A.** 4
- **B.** 6
- **C.** 7
- **D.** 9
**答案：C**
> 分类：数学

## 3. [多选] 以下是偶数的是？
- **A.** 2
- **B.** 3
- **C.** 4
- **D.** 5
**答案：AC**

## 4. [填空] 定义函数用 ____ 关键字，返回值用 ____。
**答案：def；return**

## 5. [简答] 简述什么是闭包。
**答案：闭包是引用了自由变量的函数。**
```

**识别规则**
- 题号起始：`## 1.` / `1.` / `1、` / `(1)` / `第1题` 均可（井号与列表符会先被清洗）。
- 题型内联：紧跟题号的 `[单选]` / `[单选题]` / `（多选）` 等；缺省时按选项/空位/布尔答案推断。
- 选项行：`- **A.** 文本` 或 `A. 文本`。
- 标记行：`**答案：X**` / `答案：X`；`> 解析：…`；`> 分类：…`（分类会写入 `category`）。解析类标记同样支持 `解题思路：/考点：/释义：` 等（见 §5 标记行清单），多段合并到 `analysis`。
- 填空各空答案用 `； ; | 、` 分隔，数量与题干 `____` 对齐。

### 6.1 材料题块（M2-A）

材料题用一个「材料块」表示：**顶层题号内联 `[材料题]` 开块 → `材料：` 共享材料（可跨行）→ 若干 `(i). [题型]` 小问 → 下一个顶层题号自动收块**。本系统导出即权威排版，导出 → 再导入 contentHash 无损：

```markdown
## 1. [材料题] 根据上述资料，回答下列问题。
材料：甲公司为增值税一般纳税人，2026 年 3 月购入一台不需安装的生产设备，
取得专票价款 10000 元，另支付运输费 2000 元。
> 难度：3
> 标签：综合题、固定资产
> 分类：会计基础
(1). [单选] 该设备的入账价值为（ ）元。
> 分值：25
- **A.** 10000
- **B.** 12000
**答案：B**
> 解析：买价 10000 加运输费 2000。
(2). [判断] 购入即达到预定可使用状态。
**答案：正确**
(3). [简答] 简述运输费计入资产成本的理由。
**答案：运输费是使资产达到预定可使用状态前的必要支出。**

## 2. [单选] 下一道普通题……
```

**切词规则**

- 开块标记：顶层题号行内联**带括号**的 `[材料题]` / `[综合题]` / `[组合题]` / `[材料]`（半角全角括号均可）。括号强制：题干正文中裸出现的「材料」「综合」字样（如「购入材料一批」）不会开块。
- 材料行：`材料：` 起始，后续续行（含 `![](asset:id)` 图片占位）自动并入，直到第一个小问；允许空行（导入时空行被忽略，不能用于划界）。
- 小问起始：`(1)` / `（1）` / `(1).` / `(1)、` / `(1)：`；容错识别 `1-1` / `1–1` 形式（取第二序号，**导出统一用 `(i)`**）。小问仅在材料块内按小问切分，普通题中的 `(1)` 编号行为不受影响。
- 小问体：题型内联标记 + 选项/答案/解析规则与普通题完全一致；**小问分值行** `分值：N`（Markdown 可带 `> `，DOCX/TXT 同语义）仅在小问上下文生效，回填 `children[*].score`（1–100，M4）；填空 `accept`/`hint` 无行式语法，行式往返保留标准答案（不影响 contentHash，完整字段请用 JSON/.qbk）。
- 父题元数据：`难度：/标签：/分类：/解析类标记` 放在**第一个小问之前**归父题；小问之后出现的这些行忽略（子问题继承父题）。父题 `解析：/解题思路：/考点：/释义：` 均同，多段合并到父题 `analysis`；父题解析标记后的多行续行（含合并后的 `【释义】/【考点】` 分段）在小问出现前归父题解析，不误入材料正文。
- 收块：下一个顶层题号（`2.` / `2、` / `第2题`；裸 `(2)` 不算）或文件结束。

**容错（不阻断，导入预览给警告）**：无 `材料：` 标记时开块后、首个小问前的文本按材料正文处理；小问序号不连续；小问数 <2 或 >10（标准模型校验）。样例：`示例-材料题.md`（材料块 + 1 道普通题，覆盖收块边界）。

> Markdown 主要面向**阅读与往返备份**；需要 Excel 打开请用 CSV，需要保留完整结构化字段（`source`、备选答案 `accept` 等）请用 JSON。

### 6.1 粘贴文本导入（与文件 / 拖拽 / URL 同一解析路径）

首页「粘贴文本导入」不维护第二条解析链，而是把剪贴板文本包装成虚拟文件名后调用 `QB.Importers.runImport`，与文件、拖拽、URL 三个入口共用同一注册表与 `sniff` 判定：

| 顺序 | 虚拟文件名 | 命中条件 | 结果 |
| --- | --- | --- | --- |
| 1 | `粘贴.json` | 文本以 `{` / `[` 开头且 JSON 语法有效 | JsonImporter（`format` 以 `json` 开头，带 `meta`） |
| 2 | `粘贴.txt` | 注册表按扩展名分派（Quizlet `priority` + `sniff` 先于 CSV） | Quizlet 两列 term/definition（Tab / 逗号 / 全角逗号 / 分号 / 竖线）；含表头 CSV 仍走 CSV |
| 3 | `粘贴.md` | 前两步均未命中（如 Markdown 标题行式、`[材料题]` 行式块） | MdImporter/LineParser，行为与 Markdown 文件完全一致 |

- 文本以 `[` 开头（行式材料块）时，JSON 语法失败会回退到第 2/3 步，不会被误判为「JSON 损坏」而直接失败。
- 粘贴弹窗文案明确说明支持「Quizlet 的 term/definition」两列文本；不支持的纯文字仍保留原「解析失败：未能从 Markdown 中识别出题目」提示。
- **一致性约定**：同一文本经粘贴、文件（`.txt`）、拖拽或 URL 导入，题数/题型/`format`/`warnings` 必须完全一致（D1 回归断言见 `scripts/importers-quizlet.test.mjs`）。
